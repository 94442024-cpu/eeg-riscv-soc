# Contributing

Keep changes focused and document interface changes in `docs/`.

Before opening a pull request:

- run the relevant directed tests
- run the full available regression
- include the simulator and tool versions
- update the verification plan when behavior or coverage changes
- avoid committing generated simulation, synthesis, or physical-design output

Use small commits that describe one logical milestone, for example `Add RV32I register file model` or `Verify load sign extension`.
